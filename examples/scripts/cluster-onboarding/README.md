# Cluster Onboarding

Cluster onboarding scripts that take a cluster from "just provisioned" to "ready for RHACM Spoke onboarding via Ansible". Scripts 01 and 02 are required for all clusters.

## Workflow

### Step 1 -- Register the cluster

[*`01_register_cluster.sh`*](01_register_cluster.sh)

Interactive login and context registration. Prompts for the API URL, username, and
password, validates cluster-admin privileges, and registers a named kubeconfig context.
Auto-detects the context name from **`Infrastructure.status.infrastructureName`** unless you
provide a custom one.

```bash
./examples/scripts/cluster-onboarding/01_register_cluster.sh
```

### Step 2 -- Provision the automation ServiceAccount

[*`02_provision_automation_sa.sh`*](02_provision_automation_sa.sh)

Idempotent provisioning of the **`ansible-dr-orchestrator`** ServiceAccount in the
**`ansible-automation`** namespace (cluster-admin **`ClusterRoleBinding`** + long-lived bearer
token). Creates the **`<cluster>-sa`** kubeconfig context and writes a per-cluster **`.env`** file
to **`~/.kube/clusters/<context>.env`**.

```bash
# Interactive (picks from available kubeconfig contexts):
./examples/scripts/cluster-onboarding/02_provision_automation_sa.sh

# Non-interactive (pass the context name):
./examples/scripts/cluster-onboarding/02_provision_automation_sa.sh my-cluster
```

## Credential modes

- **Per-cluster **`.env`** files** (primary): each cluster gets its own
  **`~/.kube/clusters/<context>.env`** containing **`ACM_CLUSTER_HOST`**, **`ACM_CLUSTER_TOKEN`**,
  **`ACM_CLUSTER_CA_DATA`**, and **`ACM_CLUSTER_CONTEXT`**. Generated by Step 2. Loaded into
  role-prefixed vars by [*`load_cluster_env.sh`*](../lib/load_cluster_env.sh).
- **Monolithic kubeconfig** (legacy): all contexts live in a single **`KUBECONFIG`** file.
  Still supported by the [DR orchestrator](../dr-orchestrator/).

## What comes after

Once the SA context is in place (Step 2), RHACM Spoke onboarding happens via the Ansible playbook.

```bash
ansible-playbook playbooks/manage-spoke.yml \
    -e acm_dr_spoke_manager_action=prep \
    -e k8s_target_context=acm-primary-hub-sa \
    -e acm_dr_spoke_manager_spoke_context=my-cluster-sa

---

## Known limitations by distribution

### Step 1 (`01_register_cluster.sh`) - OCP-only

`01_register_cluster.sh` uses `oc login` with username and password and reads the cluster name from `oc get infrastructure cluster`. It works for OpenShift distributions (ARO Classic, ARO HCP, ROSA, OCP) but not for non-OCP distributions. For AKS, EKS, GKE, and IKS, register the kubeconfig context manually via the provider's native CLI before running Step 2:

```bash
# AKS
az aks get-credentials --resource-group <rg> --name <cluster> --context <desired-context-name>

# EKS
aws eks update-kubeconfig --name <cluster> --alias <desired-context-name>

# GKE
gcloud container clusters get-credentials <cluster> --region <region>
kubectl config rename-context gke_<project>_<region>_<cluster> <desired-context-name>

# IKS (VPC endpoint: see note below)
ibmcloud ks cluster config --cluster <cluster-id> --alias <desired-context-name>
```

After registering the context, proceed directly to Step 2 (`02_provision_automation_sa.sh`).

### GKE Autopilot - not supported as a Spoke

GKE Autopilot clusters deny `cluster-admin` ClusterRoleBindings and block direct reads on `/api/v1/nodes`. Both are required by the RHACM klusterlet bootstrap and by the Stage 00 preflight in the failover manager. Use GKE Standard mode clusters instead.

### IKS VPC - private API endpoint

IKS clusters in VPC mode expose a private API endpoint that is not reachable from outside the IBM Cloud network without a VPN or transit gateway. The kubeconfig generated by `ibmcloud ks cluster config` contains the private endpoint URL. If the automation host has no VPN access to the IBM Cloud VPC, all `kubectl`/`oc` calls to IKS will time out with `connection refused`. Confirm connectivity with `kubectl cluster-info --context <iks-context>` before running any Ansible playbook.
